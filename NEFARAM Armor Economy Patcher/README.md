# NEFARAM Armor Economy Patcher

Local Synthesis/Mutagen patcher for finding armor and clothing whose base gold value is wildly out of line with its crafting recipe. It uses official Skyrim, DLC, and Creation Club equipment as read-only reference data and never overrides those records.

The default is deliberately safe: **audit only**. An audit run writes:

- `C:\Users\antho\nefaram-files\artifacts\armor-economy-audit.csv`
- `C:\Users\antho\nefaram-files\artifacts\armor-economy-audit.json`

## Behavior

- Scans winning `ARMO` records that have winning `COBJ` crafting recipes.
- Excludes armor-table and sharpening-wheel tempering recipes; their one-material upgrade costs are not creation costs.
- Excludes Bethesda/Creation Club outputs from patch targets.
- Matches an added item to official equipment by armor type, one primary body slot, and material.
- Uses material keywords first and recipe ingredients only when they give an unambiguous result.
- Automatically flags only the exploit pattern: the output is worth at least four times its ingredients, exceeds the comparable official markup by at least 3x, and differs by at least 100 gold.
- Excludes enchanted outputs, unsupported slots, ambiguous modular pieces, and custom materials from automatic changes.
- In apply mode, normalizes recognized crafting-material entries and caps base value at the greater of the official reference value or twice the normalized ingredient cost. It preserves special/custom recipe ingredients, conditions, perks, station, output count, armor rating, name, enchantment, and assets.

This is an ESP patch generated by Synthesis. It is not an in-game Papyrus script and it does not edit any installed armor mod.

## Normal workflow

1. Close Skyrim. MO2 itself may remain open when launching one of its executables.
2. Run **NEFARAM Armor Economy Audit** from MO2.
3. Open `artifacts\armor-economy-audit.json` and review `summary`,
   `changesByPlugin`, and then `changes`.
4. If the proposed list is acceptable, run **NEFARAM Armor Economy Build**.
5. Confirm `[NoDelete] NEFARAM Armor Economy Patch` and
   `NEFARAM_ArmorEconomyPatch.esp` remain enabled. Keep the plugin after its masters.

Run the audit again whenever armor mods or their recipes change. The Build command is
deterministic and replaces only its own generated ESP.

## Reading the JSON report

The JSON deliberately puts the useful review material first:

- `summary`: total records, proposed changes, applied changes, and status totals.
- `changesByPlugin`: compact count of proposed changes from each source plugin.
- `statusGuide`: plain-language meaning of every status.
- `changes`: only high-confidence before/after candidates. In apply mode,
  `patched: true` confirms that pair was written to the ESP.
- `needsReview`: interesting records the conservative rules refused to change.
- `otherRecords`: within-range or ambiguous records retained for completeness.

For each entry in `changes`, compare `originalValue` with `proposedValue` and
`ingredients` with `proposedIngredients`. `referenceFormKey`, `referenceValue`, and
`referenceIngredientValue` show the official item used as the balancing reference.
The CSV contains the same record-level fields for filtering in a spreadsheet.

## Synthesis integration

The NEFARAM runtime pipeline contains a final `Synthesis_5` group pointing to this local solution. Its output is `Synthesis_5.esp` in the existing `Synthesis Output` mod.

MO2 has two direct launchers that run the compiled patcher through its virtual filesystem:

- `NEFARAM Armor Economy Audit` uses the audit-only settings and writes reports under `artifacts`.
- `NEFARAM Armor Economy Build` uses a separate apply-mode settings folder, excludes `Vigilant.esm`, and generates `NEFARAM_ArmorEconomyPatch.esp` inside the standalone `[NoDelete] NEFARAM Armor Economy Patch` mod.

Run Synthesis through the NEFARAM MO2 instance. The first run is audit-only and should be reviewed before changing settings.

The audit runtime settings are at `C:\games\nefaram\tools\Synthesis\Data\Skyrim Special Edition\NEFARAM Armor Economy Patcher\settings.json`. The build settings are isolated at `C:\games\nefaram\tools\Synthesis\Data\Skyrim Special Edition\NEFARAM Armor Economy Build\settings.json`. The project also bundles audit-safe defaults for a fresh installation.

| Setting | Meaning |
|---|---|
| `AuditOnly` | `true` writes reports without overrides. `false` permits selected high-confidence changes. |
| `ValueOutlierFactor` | Added gear must exceed the comparable official crafting markup by this multiplier. Default: `3.0`. |
| `MinimumExploitMarkupRatio` | Added gear value divided by its ingredient cost must reach this ratio. Default: `4.0`. An 800g item made from 20g of materials has a ratio of 40. |
| `TargetCraftingMarkupRatio` | Used when calculating the corrected value cap from the reference recipe. Default: `2.0`. |
| `MinimumGoldDifference` | Ignore small discrepancies below this many gold. Default: `100`. |
| `MaximumMasters` | Refuse an apply run above this direct-master safety limit. Default: `240`. |
| `ReportDirectory` | Folder receiving `armor-economy-audit.json` and `.csv`. |
| `ExcludedPlugins` | Plugin filenames that are never patch targets. The current build contains `Vigilant.esm`. |
| `ExcludedFormKeys` | Individual added armor FormKeys to omit, such as `001234:Example.esp`. |
| `ApplyOnlyFormKeys` | Optional allow-list. When non-empty, only these high-confidence FormKeys are written. |
| `ForcedReferenceMappings` | Optional map from an added armor FormKey to an official reference armor FormKey. |

JSON has no standard comment syntax, so explanatory text belongs here rather than in
`settings.json`. Keep plugin names and FormKeys in their exact report spelling.

The first reviewed build generated 198 high-confidence overrides and excluded all VIGILANT targets. After later load-order changes, run the Audit launcher first and review its report before regenerating with the Build launcher.

## Safety details

- The patcher hard-excludes `Skyrim.esm`, `Update.esm`, the three DLC masters, `_ResourcePack.esl`, and every plugin beginning with `cc` from target overrides.
- Apply mode aborts before writing overrides when the conservative direct-master estimate exceeds `MaximumMasters`.
- Source stays in this repository; only Synthesis's generated output belongs in the runtime MO2 instance.
